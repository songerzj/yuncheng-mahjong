# 运城麻将（yuncheng-mahjong）

运城本地麻将的 Web 版实现：多人实时联机 + AI 自动补位，内置**扣点点 / 红中 / 贴金**三种运城流行玩法。纯 Node.js 后端 + 原生前端，无需打包构建，开箱即跑。

> 原名 `koudian-mahjong`（扣点点麻将），现已统一更名为「运城麻将」并支持多玩法。

---

## ✨ 功能特性

- **三种玩法共存**：扣点点、红中、贴金，规则独立实现于 `src/rules.js`
- **实时联机**：基于 WebSocket（`ws`）的房间制对局，断线可重连
- **AI 补位**：人数不足时 AI 自动入座代打，支持玩家「托管」
- **AI 难度逐座位可选**：普通（原有启发式）/ 困难（向听数 + 进张数 + 点炮风险 + 碰牌牌效），可在房间内给每个空位分别添加普通或困难人机，同一局混搭；已入座的 AI 也能随时切换难度
- **AI 胜率自动校准**：困难档记录决策复盘，按实测胜率 / 放铳率小步自动调参，无需重启服务
- **账号系统**：注册 / 登录 / 登出，密码使用 scrypt 加盐哈希，token 会话
- **历史对局**：已登录玩家的每局结算自动落盘，可随时回看
- **聊天系统**：对局内文字聊天 + 10 条常用语快捷胶囊
- **对局表情互动**：白名单 emoji 一键发送，桌面浮动展示，迟到者可补看
- **好友系统**：添加好友（双向请求/互加）、好友请求接受/忽略/删除，关系变更实时推送
- **战绩与排行榜**：个人胜率/净积分/单局最佳聚合；全局积分排行榜
- **房间邀请分享**：一键复制邀请链接（含房间号），生成二维码，好友打开即加入
- **移动端适配**：竖屏/横屏/超小屏响应式布局，弹窗可滚动
- **语音播报（TTS）**：可选本地 TTS 桥接（见 `src/tts-bridge.js`）
- **安全加固**：重连防劫持、房间码防枚举、WebSocket 帧限流与负载上限
- **日志异步化**：按大小轮转，不阻塞主流程

## 🀄 三种玩法简介

| 玩法 | 关键机制 |
| --- | --- |
| **扣点点** | 运城主流玩法，开局扣倍数、点炮/自摸计分，强调「点」的扣减与倍数 |
| **红中** | 红中作万能牌（赖子），可杠可胡；结算采用简化番制 |
| **贴金** | 贴金（金钓）玩法，规则实现最贴合网络通用版本 |

> 规则细节以 `src/rules.js` 与对应测试（`test/rules-*.test.js`、`test/game-*.test.js`）为准。若与你本地实际玩法有出入，欢迎提 issue 校正。

### 🤖 AI 难度

三种玩法通用。**难度按座位选择，不是整房固定一种**：

- 建房弹窗里的「默认 AI 难度」对应 `settings.aiDifficulty`（`normal` / `hard`，默认 `normal`），只用于**开局自动补位的机器人、真人托管/断线代打**，以及旧客户端兼容。
- 建房后，房主在等待房/结算页的**每个空座位**上都有「＋普通」「＋困难」两个按钮，可给不同座位指定不同难度；已入座的 AI 座位显示难度徽标，点一下即可切换（`set_ai_difficulty`），**牌局进行中切换也在下一次决策立即生效**。
- 实际难度存在 `room.players[seat].aiDifficulty`，由 `src/ai-difficulty.js` 统一解析（座位值优先，未指定时回落房间默认）。大厅列表、房间信息栏、牌桌座位都会显示实际难度分布，如「AI 1困难·2普通」。
- 老客户端发 `add_ai` 不带参数仍按房间默认难度补位，行为不变。

| 难度 | 出牌决策 | 碰牌响应 | 实现 |
| --- | --- | --- | --- |
| 普通 | 对子/搭子保留价值 + 安全牌固定权重（原有行为，未改动） | 听牌则不碰，否则碰 | `src/ai.js` |
| 困难 | 枚举全部弃牌 → 向听数 → 有效进张（扣除已见绝张）→ 点数加权 → 精确点炮风险 | 对比「碰掉两牌 + 弃一牌」后的最优牌效与不碰基准；已报听不碰 | `src/shanten.js`、`src/ai-hard.js` |

困难难度的牌效思路参考《麻将概率助手电脑版》，并按运城规则改造：1/2 点进张权重为 0、3/4/5 点只算自摸（半权）、6 点以上按点数收益加权；点炮风险用服务端已知的「已报听对手听口」精确计算，而不是猜测；先比向听与可胡牌数，相差 ≤2 张时才让风险介入排序。红中/贴金用各自专用胡牌判定枚举听口并带判定预算（避免阻塞事件循环）；它们的碰牌响应因万能牌没有通用向听，改用「碰掉唯一对子会失去雀头」的轻量判据。任何局面下困难策略无有效解都会回退普通策略，AI 不会卡死。

### 📈 AI 胜率复盘与自动校准

困难档会持续记录自己的决策与结果，形成「打法 → 胜率 → 调参」的闭环（思路来自电脑版的 `training_journal`）：

- 每次困难决策把候选弃牌的向听 / 进张 / 风险 / 实际选择写入 `logs/ai-YYYY-MM-DD.jsonl`；本局结算后再按 AI 座位写入结果（是否胡牌、是否放铳、本局净得分）。**混合难度房间按座位难度分条写**（normal / hard 各一条），避免把普通样本算进困难档统计。日志复用 `game-logger.js` 的异步写盘、大小轮转与 7 天清理，不阻塞对局。
- 服务端在内存里维护滚动窗口，**累计满 40 条困难档「AI 座位·局」记录即自动校准一次**（一局 3 个 AI 就记 3 条，约合 14 局左右）：放铳率超标就转防守、胜率偏低且防守未失控就转进攻、明显强于目标就向默认参数收敛。参数写入 `data/ai-calibration.json`（原子写），`ai-hard.js` 每次决策读取，**无需重启服务**。
- 可调参数只有 4 个且被严格限制：`defenseSlack`（风险介入范围 0–5）、`riskWeight`（弱风险线索 0.5–2）、`winWeightBoost`（高点数收益 0.8–1.3）、`pengAggression`（碰牌收益门槛 0.8–1.2）。单次调整不超过固定步长，文件损坏 / 字段非法一律回退默认值；`MARVIS_AI_CALIBRATION=0` 可关闭，`MARVIS_AI_CALIBRATION_MIN_ROUNDS` 可改样本门槛。
- 人工复盘与回滚：`npm run ai:stats` 查看分玩法 / 难度的胜率、放铳率、净得分；`npm run ai:calibrate` 用全量历史重算参数；`node scripts/ai-calibrate.js --reset` 恢复默认。加 `--dry-run`、`--json`、`--log-dir`、`--min-rounds` 可做只读预览与诊断。

> 校准只作用于困难档；普通档是固定策略，不参与学习，仅展示统计。

### 🧪 AI 强度基准（批量模拟）

`npm run ai:sim` 在纯内存里驱动真实 `GameServer` 批量对局（可复现种子、2 普通 + 2 困难同桌、同一批牌山难度对调配对），`npm run ai:sim:report` 做按 seed 聚类的 bootstrap 检验并生成报告。完整参数见 `scripts/README.md`。

10000 局扣点点基准（固定默认参数）：困难和牌率 **25.17% vs 普通 19.98%**（+5.19pp，p<0.001），放铳率 12.33% vs 14.22%，每座位·局净得分 +2.607 分（95% CI [2.054, 3.205]）。约 **84% 的优势来自进攻端**（更多和牌 + 更高点数），16% 来自少放铳；困难档赢家里低点听口占比 9.18% vs 12.31%，说明点数加权确实起作用。全困难房和牌率 92.6% vs 全普通房 87.4%。

> ⚠️ 已知问题：校准目标胜率 30% 在 4 家零和的纯 AI 房里数学上不可达（平均锁在 25%），长跑会把 3/4 参数推到边界并来回振荡。生产建议只统计含真人的房间，或把目标改为「相对同桌其他座位净得分 > 0」。完整分析见本地 `reports/ai-sim-report.md`（该目录已 gitignore，需自行运行脚本生成）。

## 🧱 技术栈

- **运行环境**：Node.js 18+
- **后端**：原生 `http` + `ws`（WebSocket）+ `selfsigned`（本地 HTTPS 自签证书）

## 👤 账号与历史对局

- **注册**：用户名 ≤ 16 字符，密码使用 `scrypt` 加盐哈希存储（**不存明文**）。
- **登录**：签发 token 作为会话凭证，前端自动保存并用于重连。
- **历史对局**：每局结束若为已登录玩家，结算结果写入 `data/history/<用户名>.jsonl`，可在「对局记录」面板回看。

---

## 💾 数据存放位置与更新安全

所有用户数据都保存在项目根目录的 **`data/`** 文件夹内，与代码完全分离：

| 文件 / 目录 | 存放内容 |
| --- | --- |
| `data/users.json` | 账号信息（用户名、密码哈希、昵称、注册时间） |
| `data/friends.json` | 好友关系与待处理的好友请求 |
| `data/history/<用户名>.jsonl` | 每个用户的历史对局记录（一局一行） |

### 🔒 更新代码不会覆盖数据

`data/` 目录已在 `.gitignore` 中忽略，**不会进入 Git 版本库**。因此：

- ✅ `git pull` 拉取最新代码、重新部署、重装依赖时，`data/` 里的账号与对局记录都会**原样保留**。
- ✅ 代码与数据分离开，升级/回滚版本都不影响已有用户数据。

### ⚠️ 唯一需要留意的情况

- 若你设置了环境变量 `KD_DATA_DIR`，数据会改存到该变量指定的目录（默认才是 `data/`）。确认备份时请以实际生效目录为准。
- 只有手动删除 `data/` 文件夹、或显式运行「注销账号」功能，才会真正删除数据。**如需迁移或备份，直接拷贝整个 `data/` 目录即可**。

## 🔒 安全设计

| 风险 | 措施 |
| --- | --- |
| 重连劫持 | 每局生成 `crypto.randomBytes` 密钥，重连需双因子校验 |
| 房间码枚举 | 房间码用 `crypto.randomInt` 随机生成 + 失败锁定 |
| 消息洪泛 | WebSocket 令牌桶限流（约 60 msg/s），`maxPayload` 16KB 帧上限 |
| 单 IP 多开 | `MAX_WS_PER_IP` 连接数上限 |
| 凭证泄露 | 密码仅存哈希；`.ghtoken` 等临时凭据文件已 gitignore |
